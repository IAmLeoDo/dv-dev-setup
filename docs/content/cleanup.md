# Cleanup and Tool Removal

[Documentation index](../index.md)

Run cleanup inside Ubuntu/WSL as the development user. Every command previews
a summary by default: directories/tools to remove, selected packages to
uninstall, tools to keep, and matching shell initialization edits. Without
`--apply`, it reads inventory and sizes only; it does not run APT simulations,
uninstallers, sudo, deletion, or startup-file edits. Missing items are omitted.
No files are removed until `--apply` is supplied and you confirm the plan. `--dry-run` explicitly selects the same preview mode.
For an already reviewed automated plan, `--apply --yes` skips the terminal prompt.
`DV_DRY_RUN=true` prevents applying cleanup even if `--apply` is passed.

## Clean the Whole Managed Environment, Keeping Selected Tools

```bash
dv cleanup all                                 # Preview managed tools + caches
dv cleanup all --keep dv,pyenv,nvm               # Keep CLI and both managers
dv cleanup all --keep dv,pyenv,nvm --apply       # Confirm, then apply that plan
dv cleanup all --apply                          # Remove all selected managed tools
```

`all` selects the installed dv runtime/CLI/managed aliases, pyenv and all its
Python versions/libraries, nvm and all its Node versions/global packages, default
caches, and recorded APT development packages. It does not recursively scan
projects or delete project `.venv`/`node_modules`; select a project separately.

Accepted `--keep` names are `dv`, `pyenv`, `nvm`, `docker`, `git`, `ssh`, and
`packages`, separated by commas. `python` and `node` also mean `pyenv` and `nvm`.
Keeping a manager keeps its installed versions and known recorded prerequisites:
pyenv keeps Python build libraries and Git, nvm keeps build-essential and Git,
and dv keeps Git. `packages` keeps all APT packages. Cache cleanup can still run
for tools that are kept; installed versions are preserved.

If dv is removed, its generated alias file and CLI symlink are removed too.
User settings in `~/.config/dv/config.ini`, tool update backups, setup state, and
SSH keys remain. Use an extracted bundle/source to install dv again. Removing
pyenv/nvm removes all versions and packages under those managers, not system
Python/Node installations or unrelated user package directories. Existing
projects may need their environments recreated if their base interpreter was
removed.

## Remove Just Selected Tools

```bash
dv cleanup tools nvm                            # Preview nvm + every Node version
dv cleanup tools pyenv --apply                  # Remove pyenv after confirmation
dv cleanup tools dv --apply                     # Remove installed dv and its aliases
dv cleanup tools docker --include-existing      # Preview older Docker APT packages
dv cleanup tools --keep dv,docker --apply        # Remove other managed tools
```

`tools` with no names selects dv, pyenv, nvm, and recorded development packages.
Supplying names narrows the selection; `docker`, `git`, `ssh`, and `packages`
select the corresponding recorded APT packages. `ssh` covers keychain;
openssh-client and SSH key/config files are preserved.

Cleanup backs up `~/.bashrc` under
`~/.local/state/dv-dev-setup/cleanup-backups/` before removing exact initialization
lines previously generated by setup. Custom shell lines are preserved. Symlinked
or non-writable startup files require manual review. Open a new Bash shell after
tool removal; a child process cannot unload aliases/functions from the current
terminal. Switching or deactivating selected active runtimes is required before
applying their removal.

## Clean Caches or Project Libraries

```bash
dv cleanup                                      # Preview default caches
dv cleanup cache --apply                         # Confirm cache removal
dv cleanup project ./my-project                  # Preview .venv and node_modules
dv cleanup project ./my-project --only node       # Preview node_modules only
dv cleanup project ./my-project --only python --apply
```

Cache cleanup covers default `~/.cache/pip`, `~/.npm/_cacache`, and download
caches under configured pyenv/nvm roots. Custom pip/npm cache locations are not
automatically discovered. Managed cache/version paths must be inside the Linux
home directory. Manager directories are recognized before whole-tool removal.

Project cleanup targets only the explicitly named project's `.venv` and/or
`node_modules`. A virtual environment needs `pyvenv.cfg`; Node dependencies need
`package.json` in the selected project. Git-tracked dependency paths are refused.
Source files, `.git`, manifests, and lockfiles are preserved. The selected
dependencies are deleted, not archived; reinstall them with the project's normal
workflow afterward. Deactivate a selected virtual environment before applying.

## Uninstall One Exact Runtime Version

```bash
dv cleanup python 3.13.12                         # Preview exact pyenv version
dv cleanup node 22.14.0                           # Preview exact nvm version
dv cleanup node 22.14.0 --apply
```

Only full versions are accepted, not `system`, `lts/*`, `latest`, or prefixes.
Python removal uses pyenv uninstall; Node removal uses nvm uninstall. Manager
roots and other versions are preserved. The selected version's installed
libraries/global packages are removed with it. No upstream nvm initialization is
executed during preview. Project version files and manager defaults are not
rewritten automatically; review references to a removed version afterward.

## Remove Development APT Packages

Setup now records packages it found missing and successfully installed in
`~/.local/state/dv-dev-setup/installed-packages.txt`. Existing packages are not
claimed by setup. Automatic package selection uses that record and a fixed
allowlist of development packages, and removes journal entries only after
successful package removal.

For installations made before ownership tracking, choose exact packages or
explicitly include preexisting allowlisted packages:

```bash
dv cleanup packages docker-ce docker-ce-cli       # Preview exact selection
dv cleanup packages libssl-dev --apply
dv cleanup all --include-existing --keep dv,git    # Broader explicit preview
```

The allowlist covers Git, keychain, build-essential, Python build development
libraries installed by setup, and Docker CE/CLI/Compose/Buildx/containerd.io.
Baseline Ubuntu Python, ca-certificates, curl, openssh-client, gnupg, and xz-utils
are preserved. No wildcards, purge, or autoremove are supported.

The summary lists selected installed APT packages without running APT.
With `--apply`, dependency validation runs an APT removal simulation before
confirmation. If APT proposes removing additional
packages outside the exact selected set, cleanup stops so you can narrow the
selection or explicitly select additional allowed packages. Only APT removal
uses sudo; never run the entire command as root. A running Docker/containerd
process blocks removal of its packages: save container work and stop the selected
services manually first. Cleanup does not stop services or remove Docker data,
volumes, images, repository configuration, or signing keys.

## Boundaries and Recovery

- Preview/help do not create backups, write state, initialize managers, or remove files.
- All paths are validated before applying. Symlinked targets and directory paths,
  mount points, protected config/key directories, and filesystem/home roots are refused.
- Managed tool directories require recognizable runtime/manager files. Unrelated
  CLI files and aliases are preserved, with an actionable error.
- Tool removal shares the installed-runtime lock with setup/install. A failed
  external package/manager command returns failure; subsequent removals stop.
- Deletions are not transactional across APT, managers, and filesystem operations.
  Review a failed command's output and remaining state before retrying.
- Runtime update backups and user configuration remain for recovery; cleanup does
  not silently delete them to reclaim space.
