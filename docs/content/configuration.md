# Configuration

[Documentation index](../index.md)

Edit **`src/app/config.ini`**, beside `dev.sh` and `dev.bat`. The packaged equivalent is `dist/vX.X.X_yyMMdd_HHmmss/config.ini`.
On first setup/install, this template also initializes `~/.config/dv/config.ini`.
Edit that persistent user file after installation. Installed tools load their
copied `config.ini` defaults, then this user override. Existing environment
variables still take priority; explicit `DV_CONFIG` selects a different override.
Source setup/install commands also use this persistent override when it exists.
Reinstalling tools preserves the user file, so later edits to a downloaded
bundle's template do not replace existing user settings.

| Section | Purpose |
| --- | --- |
| `[setup]` | `DV_KEY=value` assignments for Ubuntu setup |
| `[aliases]` | Ubuntu Bash shortcuts generated by the aliases module |
| `[ssh]` | Template for `~/.ssh/config`, created only when the file does not exist |
| `[vscode.extensions]` | Extension recommendations to apply manually in the appropriate host/guest UI |
| `[vscode.settings]` | Sample JSON settings to merge manually |
| `[wsl2]`, `[experimental]` | Windows `.wslconfig` generation with confirmation and backup |

## Ubuntu Values and Overrides

In `[setup]`, use one `DV_KEY=value` assignment per line. Full-line comments start with `#`; values may be enclosed in one matching pair of quotes. Inline comments, escapes, and command substitution are not supported. Literal `$HOME` is replaced with the current home directory. SSH and VS Code templates are read as data, never sourced or evaluated.

Set `DV_CONFIG=/absolute/path/config.local.ini` to load a private override. The main configuration supplies defaults; the override only needs the values or sections you want to change. Existing environment variables take precedence over `[setup]` values. Legacy override files may contain assignments without a `[setup]` header. Alias/SSH/VS Code overrides replace the entire corresponding section.

| Option | Meaning / default |
| --- | --- |
| `DV_TOOLS_ROOT` | Tool storage root, default `$HOME/.local/share/dv-dev-setup`; setup copies the Linux runtime to `app/` beneath it. Installed tools infer their own root unless the environment explicitly selects another target. |
| `DV_ORG` | Organization label: `devimony`; letters, digits, hyphens, and underscores |
| `DV_WORKSPACE_ROOT` | Absolute root: `$HOME/workspace`; must not be under `/mnt/` |
| `DV_PROJECTS_ROOT` | Project root: `$HOME/workspace/devimony`; update separately when changing the workspace |
| `DV_GITHUB_USER` | SSH key comment label: `iamleodo`; not a credential |
| `DV_GIT_DEFAULT_BRANCH` | `main`; applied only if `init.defaultBranch` is unset |
| `DV_GIT_NAME`, `DV_GIT_EMAIL` | Empty preserves identity; conflicting new values require confirmation |
| `DV_PYTHON_VERSION` | Explicit Python version: `3.13.12` |
| `DV_PYENV_VERSION` | Tag for new installations: `v2.8.7` |
| `DV_NODE_VERSION` | `lts/*` or an explicit version; pin a version for reproducibility |
| `DV_NVM_VERSION` | Tag for new installations: `v0.40.4` |
| `DV_INSTALL_GIT`, `DV_INSTALL_SSH`, `DV_INSTALL_PYTHON`, `DV_INSTALL_NODE`, `DV_INSTALL_DOCKER`, `DV_INSTALL_ALIASES` | Default `true`; `false` skips the corresponding module even with `--only` |
| `DV_DOCKER_ON_DEMAND` | Default `true`: disable/stop the service and socket after setup; `false`: enable/start the service |
| `DV_SSH_GENERATE` | Default `false`; enable key creation when no key exists |
| `DV_SSH_NO_PASSPHRASE` | Default `false`; separate opt-in for a key without a passphrase |
| `DV_GITHUB_TEST` | Default `false`; test SSH authentication after the SSH module |
| `DV_DOCKER_TEST` | Default `false`; run hello-world after installation and restore the stopped state in on-demand mode if Docker was not running before the test |

`PYENV_ROOT` and `NVM_DIR` are standard upstream variables, defaulting to `~/.pyenv` and `~/.nvm`. Shell initialization respects them. `DV_DRY_RUN=true` may also be supplied through the environment.

Example with spaces in Ubuntu paths:

```bash
DV_WORKSPACE_ROOT="$HOME/workspace custom" \
DV_PROJECTS_ROOT="$HOME/workspace custom/devimony" \
bash src/app/dev.sh setup --only workspace
```

Booleans accept only `true` or `false`. Unknown keys and invalid version/path values are rejected before setup changes the system. New setup keys require explicit parser support and validation.

## Bash Aliases (Ubuntu / WSL)

Set `DV_INSTALL_ALIASES=true` in `[setup]` (the default). Edit `[aliases]`
using `name=command`, for example:

```ini
[aliases]
dvc=dv doctor
dvclean=dv cleanup
dvv=dv versions
dvw=dv workspace
gs=git status
gd=git diff
gl=git log --oneline
```

The default cleanup shortcut is `dvclean`: `dvclean all --keep dv` shows a
summary, while `dvclean all --keep dv --apply` requests execution. For existing
installations, add `dvclean=dv cleanup` to `[aliases]` in the persistent user
config and rerun alias setup; upgrades preserve that file rather than replacing it.

Names start with an ASCII letter and contain only letters, digits, or underscores.
Names must be unique. Values must exactly match one of these supported commands:

- `dv help`, `dv doctor`, `dv versions`, `dv cleanup`
- `dv workspace`, `dv workspace open`
- `dv docker start`, `dv docker stop`, `dv docker restart`, `dv docker status`
- `dv git status`, `dv worktree list`
- `git status`, `git diff`, `git log --oneline`

Values are validated as data; arbitrary shell commands, substitutions, operators,
and quoted values are rejected. Arguments can be appended when using an alias,
for example `gd --stat`. A `[aliases]` section in `DV_CONFIG` replaces the whole
section; an empty section generates no aliases.

Preview and apply from the repository root (setup copies the tools first):

```bash
bash src/app/dev.sh setup --only aliases --dry-run
bash src/app/dev.sh setup --only aliases
```

Setup generates `~/.config/dv/aliases.bash` atomically and adds one source line to
`~/.bashrc`. Setup runs in a child process and cannot change aliases in the
calling terminal. Activate them immediately in your current interactive Bash:

```bash
source "$HOME/.config/dv/aliases.bash"
type dvh
dvh
```

`dvh` is a default name; use your configured name if you renamed it. Alternatively,
open a new interactive Bash shell. Reruns replace
only the managed alias file and do not duplicate the source line. Existing
unmanaged files or symlinks at that path are rejected. Edit `config.ini` and rerun
setup to change aliases; manual edits in the generated file will be replaced.
Existing aliases with the same names are overridden in new shells; choose other
names in configuration if needed. Already open shells retain their loaded aliases.

`dv` targets use the installed copy at `DV_TOOLS_ROOT/app/dev.sh`, and the CLI
symlink points into the same installed runtime. Setup installs this copy before
creating aliases. After successful setup, the downloaded bundle or source
checkout may be moved without breaking the installed tools.
This module configures Bash inside Ubuntu/WSL, including Ubuntu VMs, and does not
configure CMD, PowerShell, Zsh, or native macOS shells. Setting the install flag
to `false` skips setup; it does not remove previously installed aliases.

## Windows Values and Overrides

Keep WSL keys unique, without inline comments or quoted values:

- `memory`: positive integer followed by `MB` or `GB`.
- `swap`: the same format, or `0`.
- `localhostForwarding`: `true` or `false`.
- `autoMemoryReclaim`: `gradual`, `dropCache`, or `disabled`.

Set an external override in CMD:

```bat
set "DV_CONFIG=C:\path\config.local.ini"
src\app\dev.bat setup 3
```

Or in PowerShell:

```powershell
$env:DV_CONFIG = 'C:\path\config.local.ini'
.\src\app\dev.bat setup 3
```

## macOS

Use the Ubuntu configuration inside your VM. No native macOS setup section is implemented.

## Distribution and Secrets

Packaging copies the current `config.ini`; never place secrets in it. External overrides referenced by `DV_CONFIG` are not packaged automatically. Merge editor settings manually to preserve existing preferences.
